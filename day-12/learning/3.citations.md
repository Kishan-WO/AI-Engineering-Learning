# Citations

A grounded answer without a citation asks the user to trust it. A citation lets them check it. It also lets me check it, in code and in the eval.

## 1. What a citation carries
Every answer returns, next to the text, a list of sources:
| Field | Why |
|---|---|
| `marker` (1, 2, ...) | the number used inside the answer text |
| `chunk_id` | exactly which stored chunk (for debugging and the eval) |
| `document_id` and `title` | which document the user can open |
| `page` (and heading path) | where to look in it |
| `text` or a short excerpt | what the claim rests on, so the user can verify at once |
| `score` | how close the match was (useful in logs, optional for the user) |

All of this was saved as metadata at ingestion (Day 11). If the parser dropped the page number, there is nothing to cite.

## 2. Inline markers
- The model writes `[1]`, `[2]` after the claims they support: "Light travels in straight lines [1]. The angle of incidence equals the angle of reflection [2][3]."
- The client turns each marker into a link or a tooltip using the `citations` list.
- Rules in the prompt (note 2): cite every factual claim, use only the numbers of the given sources, and no citation for a refusal.
- A citation per sentence is usually enough; a citation per word is unreadable.

## 3. Verifying cited IDs
The model can write `[7]` when only `[1]` to `[5]` were given. Day 4 showed that a model invents citations when it can. So the code checks:
1. Find all markers in the answer (a regular expression such as `\[(\d+)\]`, with care for `[1][2]` and `[1, 2]`).
2. Map each to the numbered sources of this request.
3. A marker that is **not in the set** is invalid: **strip it** from the text or **flag it** in the response (`invalid_markers: [7]`). I choose one and write it in `decisions.md`.
4. Build the final `citations` list from the valid markers only, in order of first use.
- Log every invalid marker with the request ID: the rate of invalid citations is a quality number (Day 15 dashboard).

### The streaming problem
The tokens have already reached the client when I find a bad marker at the end. I cannot take them back. So the stream carries the text as it comes, and the **final event** carries the verified list. The client shows markers as links only if they appear in the final list, and ignores the rest. (Notes/01 shows the events.)

## 4. What a valid citation does not prove
| Check | Answers | Done by |
|---|---|---|
| The ID exists in the retrieved set | "is this citation real?" | my code, today |
| The cited chunk **supports** the claim | "is it the right citation?" | an LLM judge or a human (faithfulness and citation accuracy, Day 14) |
| The claim is stated in the sources at all | "is the answer grounded?" | the same eval |

A model can cite `[2]` for a claim that chunk 2 does not make, and the code check passes. Today I catch the invented numbers; Day 14 measures whether the real ones are right. Task 4's hand scoring is my first look at this: while reading each answer, I open the cited chunk and check.

## 5. Source text and the user
- Show the title and page, and let the user open the chunk. The question language may differ from the source language (note 2), so the original text is what they verify against.
- For a table chunk, the excerpt should show the table as a table (Day 11), not a stream of numbers.
- A citation to a chunk the user's tenant cannot see must never occur: retrieval is already tenant-filtered (Day 10), and the citations come only from the retrieved set.

## 6. Provider-native citation features: awareness
- Some providers can take documents as input and return citations tied to exact text spans in them, with the model trained for it.
- Advantages: less prompt work, spans instead of numbers, and fewer invented citations.
- Trade-offs: tied to one provider and its message format (against my adapter, Day 6), my chunk metadata must be mapped to their document format, and the pricing and limits change. I check the current docs.
- Today I use my own markers, because I need to understand the mechanism and to keep the `LLMClient` portable. I can compare a native feature later with the Day 14 numbers.

## 7. Mistakes to avoid
| Mistake | What happens |
|---|---|
| Trusting the model's markers without a check | invented sources reach the user |
| Using chunk IDs as markers | mangled IDs, fails the check |
| Citing at document level only | the user cannot find the claim |
| Losing the page number at ingestion | cannot cite precisely |
| Calling "has a valid marker" "correct" | right form, wrong support goes unnoticed |

## 8. What I need to remember
- A citation is metadata plus a marker plus a check.
- The check proves existence, not support; support needs the eval.
- With streaming, the verified list comes in the final event.
