# Iterable vs iterator

## The one-line difference
- **Iterable:** something you can loop over. It can hand you a fresh iterator whenever you ask.
- **Iterator:** the object that actually does the looping. It remembers its position and gives you the next item each time.

An iterable is like a **book**, and an iterator is like a **bookmark** in it. You can put many bookmarks in one book, and each remembers its own place.

## The two protocols
| | Iterable | Iterator |
|---|---|---|
| Must have | `__iter__()`, which returns an iterator | `__next__()`, which returns the next item |
| Also has | | `__iter__()`, which returns `self` |
| Built-in call | `iter(x)` | `next(x)` |
| Examples | `list`, `str`, `dict`, `set`, `tuple`, `range`, your `DocumentStore` | `iter([1, 2])`, generators, file objects, `map`, `filter`, `zip` |

So **every iterator is also an iterable**, but not the other way round. A `list` is iterable but is **not** an iterator:
```python
nums = [10, 20, 30]
next(nums)          # TypeError: 'list' object is not an iterator
it = iter(nums)     # ask the list for an iterator
next(it)            # 10
next(it)            # 20
next(it)            # 30
next(it)            # StopIteration: nothing left
```

## What a `for` loop really does
```python
for x in nums:
    print(x)
```
is shorthand for:
```python
it = iter(nums)              # 1. get an iterator from the iterable
while True:
    try:
        x = next(it)         # 2. ask for the next item
    except StopIteration:    # 3. StopIteration means "done", and the loop ends quietly
        break
    print(x)
```
`StopIteration` isn't an error, it's the signal that ends the loop. That's why `for` never crashes at the end of a list.

## Comparing with JavaScript
| JavaScript | Python |
|---|---|
| iterable has `[Symbol.iterator]()` | iterable has `__iter__()` |
| iterator has `next()` returning `{ value, done }` | iterator has `__next__()` returning the value, and raising `StopIteration` when done |
| `for (const x of arr)` | `for x in arr` |
| `arr.map(...)` builds a new array immediately | `map(...)` returns a lazy iterator |

JS signals "finished" with a `done: true` flag. Python signals it with an exception.

## The big gotcha: iterators are used up
An iterator only goes forward and can't be rewound:
```python
it = iter([1, 2, 3])
list(it)     # [1, 2, 3]
list(it)     # []   <- already exhausted, and no error
```
An iterable gives you a fresh start every time:
```python
nums = [1, 2, 3]
list(nums)   # [1, 2, 3]
list(nums)   # [1, 2, 3]
```
Many built-ins return iterators, so this catches people out:
```python
doubled = map(lambda n: n * 2, [1, 2, 3])
sum(doubled)     # 12
sum(doubled)     # 0   <- the first call used it all up
```
The same goes for `filter`, `zip`, `enumerate`, generators and open files. **If you need the data twice, store it in a list first.**

## Why Python has iterators: laziness
A list holds every item in memory. An iterator produces **one item at a time, only when asked**:
```python
big = range(1_000_000_000)      # takes almost no memory; items are computed on demand
next(iter(big))                 # 0
```
Reading a 5 GB log file works the same way, because a file object is an iterator over its lines:
```python
with open("huge.log", encoding="utf-8") as f:
    for line in f:              # one line in memory at a time
        ...
```
For AI work, this is exactly how a **streaming LLM response** arrives: tokens come one at a time, and you handle each as it appears.

## Where this is in my own code
`DocumentStore` (Day 1) is an iterable:
```python
def __iter__(self) -> Iterator[Document]:
    return iter(self.storage.all())
```
Every `for doc in store:` calls `__iter__`, which returns a **new** iterator over a fresh list. That's why I can loop over `store` many times. If `__iter__` returned `self`, the store would be used up after one loop.

## Write your own iterator (the hard way)
This shows what's behind the protocol. `yield` (next topic) makes it much shorter.
```python
class Countdown:
    def __init__(self, start: int) -> None:
        self.current = start

    def __iter__(self) -> "Countdown":
        return self                      # an iterator returns itself

    def __next__(self) -> int:
        if self.current <= 0:
            raise StopIteration          # signals "done" to the for loop
        value = self.current
        self.current -= 1
        return value

for n in Countdown(3):
    print(n)                             # 3, 2, 1
```
Try `c = Countdown(3)`, run `list(c)` twice, and look at the second result.

## Common mistakes
| Mistake | What happens |
|---|---|
| Looping over `map(...)` or `zip(...)` twice | The second loop is empty, with no error |
| `len(map(...))` | `TypeError`, because iterators have no length |
| `it[0]` | `TypeError`, because iterators can't be indexed |
| `if it:` to check for items | Always `True`, because an iterator object is truthy even when empty |
| Calling `next(it)` on an empty iterator | `StopIteration` |
| `next(it, None)` | Returns `None` instead of raising, which is the safe way to get the first item |
