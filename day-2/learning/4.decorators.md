# Decorators, `functools.wraps`, and decorators with arguments

## The idea in one sentence
A decorator is a function that **takes a function and returns a (usually wrapped) function**. It adds behaviour such as timing, retries, logging or registration without changing the original function's code.

## Step 1: functions are values
As in JavaScript, a function can be passed around, stored and returned:
```python
def shout(text):
    return text.upper()

f = shout                 # no parentheses: this is the function itself, not a call
f("hi")                   # 'HI'

def apply(func, value):
    return func(value)

apply(shout, "hi")        # 'HI'
```
Decorators build on this plus **closures** (an inner function remembering variables from the outer one, from Day 1).

## Step 2: write a decorator by hand
```python
import time

def timed(func):
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        result = func(*args, **kwargs)
        print(f"took {time.perf_counter() - start:.3f}s")
        return result
    return wrapper

def slow_add(a, b):
    time.sleep(0.5)
    return a + b

slow_add = timed(slow_add)     # replace the name with the wrapped version
slow_add(1, 2)                 # prints "took 0.500s", returns 3
```
What happens:
1. `timed(slow_add)` returns `wrapper`, which remembers `func` through its closure.
2. The name `slow_add` is rebound to `wrapper`.
3. Calling `slow_add(1, 2)` now actually calls `wrapper(1, 2)`, which calls the original inside.

`*args, **kwargs` lets the wrapper accept **any** arguments and pass them through unchanged.

## Step 3: the `@` syntax
`@timed` above a function is just shorthand for the rebinding line:
```python
@timed
def slow_add(a, b):
    time.sleep(0.5)
    return a + b

# means exactly:  slow_add = timed(slow_add)
```

## Comparing with JavaScript
| JavaScript | Python |
|---|---|
| A higher-order function: `const timed = fn => (...args) => { ... }` | The same idea, with `@timed` as shorthand |
| Express middleware wraps a request handler | A decorator wraps a function |
| `(...args)` | `(*args, **kwargs)` (positional and keyword) |
| Decorators are only a TypeScript/proposal feature | Built into the language |

## Step 4: the problem `functools.wraps` fixes
After decorating, the function **looks like `wrapper`**:
```python
@timed
def slow_add(a, b):
    """Add two numbers slowly."""
    ...

slow_add.__name__    # 'wrapper'   (expected 'slow_add')
slow_add.__doc__     # None        (the docstring is lost)
help(slow_add)       # shows wrapper's signature, not the real one
```
This breaks debugging, logs, tracebacks, and **frameworks that read function names, docstrings and type hints**. FastAPI and MCP both do that.

The fix is `functools.wraps`, itself a decorator, applied to the wrapper:
```python
from functools import wraps

def timed(func):
    @wraps(func)                       # copies __name__, __doc__, type hints, etc. from func
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return func(*args, **kwargs)
        finally:
            print(f"{func.__name__} took {time.perf_counter() - start:.3f}s")
    return wrapper
```
Now `slow_add.__name__` is `'slow_add'`, the docstring survives, and `slow_add.__wrapped__` points to the original function (handy in tests).

`try`/`finally` makes the timing print even if the function raises. **Rule: always use `@wraps(func)` in a decorator.**

## Step 5: decorators with arguments
What if I want `@repeat(3)` or `@retry(times=3)`? Now there are **three layers**:
```python
def repeat(times):                     # layer 1: takes the decorator's arguments
    def decorator(func):               # layer 2: takes the function
        @wraps(func)
        def wrapper(*args, **kwargs):  # layer 3: runs on every call
            result = None
            for _ in range(times):
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator

@repeat(3)
def hello():
    print("hello")

hello()        # prints "hello" three times
```
`@repeat(3)` means two steps:
1. `repeat(3)` runs first and returns `decorator`.
2. `@decorator` is then applied to `hello`, i.e. `hello = repeat(3)(hello)`.

```
@repeat(3)  ──►  repeat(3)  returns decorator
                 decorator(hello)  returns wrapper
                 hello = wrapper
```
The inner functions can all see `times`, because of closures.

The `@retry(times, base_delay, max_delay, exceptions)` task has exactly this shape: layer 1 takes the settings, layer 2 takes the function, layer 3 contains the retry loop.

### Mistake: `@deco` vs `@deco()`
```python
@repeat          # WRONG: passes hello as `times`; repeat(hello) returns decorator, so hello becomes decorator
def hello(): ...

@repeat(3)       # right
def hello(): ...
```
A decorator with arguments **must always be called with parentheses**, even when every argument has a default: `@retry()`.

## Step 6: when does each part run?
```python
def deco(func):
    print("decorating", func.__name__)       # runs ONCE, when the def is executed
    @wraps(func)
    def wrapper(*args, **kwargs):
        print("calling", func.__name__)      # runs on EVERY call
        return func(*args, **kwargs)
    return wrapper

@deco                      # prints "decorating f" immediately, at import time
def f(): ...

f()                        # prints "calling f"
f()                        # prints "calling f"
```
Setup work belongs in the decorator body. Per-call work belongs in `wrapper`.

## Step 7: stacking decorators
```python
@timed
@repeat(2)
def hello(): ...
```
This is `hello = timed(repeat(2)(hello))`. The decorator **closest to the function is applied first**, so `timed` is the outermost layer. Calls go from the top down: `timed`'s wrapper, then `repeat`'s wrapper, then `hello`.

## Step 8: why FastAPI routes and MCP tools are decorators
Not every decorator wraps. Some just **register** the function somewhere and return it unchanged:
```python
routes = {}

def get(path):                       # a decorator with arguments, like @app.get("/hello")
    def decorator(func):
        routes[path] = func          # register the function
        return func                  # return it unchanged
    return decorator

@get("/hello")
def hello():
    return "hi"

routes["/hello"]()                   # 'hi'
```
This is the core of what `@app.get("/items")` does in FastAPI. It stores the function in the app's route table, and FastAPI then reads the function's **name, parameters, type hints and docstring** to build validation and the `/docs` page. That is also why `@wraps` matters: without it, those details are lost.

The same applies to MCP, where `@mcp.tool()` registers a function as a tool and uses its **docstring and type hints** to describe it to the model.

```python
@app.get("/documents/{doc_id}")      # FastAPI
def read_document(doc_id: str): ...

@mcp.tool()                          # MCP (Day 17)
def search_docs(query: str) -> list[str]:
    """Search the document store."""
```

## Step 9: typing a decorator (preview)
`mypy --strict` needs to know that the wrapper has the same signature as the original. The tool for that is `ParamSpec`:
```python
from collections.abc import Callable
from functools import wraps
from typing import ParamSpec, TypeVar

P = ParamSpec("P")     # the original function's parameters
R = TypeVar("R")       # the original function's return type

def timed(func: Callable[P, R]) -> Callable[P, R]:
    @wraps(func)
    def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
        ...
        return func(*args, **kwargs)
    return wrapper
```
Typing is covered properly in the next topic. For now: `Callable[P, R]` means "a function with these parameters and this return type".

## Step 10: async functions need an async wrapper (preview)
A normal wrapper around an `async def` function breaks it:
```python
@timed                    # sync wrapper
async def fetch(): ...

fetch()                   # wrapper runs func(), which just creates a coroutine and returns it
                          # the timing is measured before the work even starts
```
For `async def` functions I need an `async def wrapper` that uses `await func(...)`. That is why the task asks for **sync and async versions** of `@retry`.

## Common mistakes
| Mistake | What happens |
|---|---|
| Forgetting `return result` in the wrapper | The decorated function always returns `None` |
| Forgetting `return wrapper` | The function name becomes `None`, and calling it gives `TypeError: 'NoneType' object is not callable` |
| Forgetting `@wraps(func)` | Wrong `__name__` and `__doc__`; frameworks and logs misbehave |
| `@deco` when it needs `@deco()` | The function is passed as the argument instead of the settings |
| Wrapper without `*args, **kwargs` | Fails on any call with different arguments |
| Putting per-call work in the decorator body | It runs only once, at definition time |
| Using a sync wrapper on an `async def` | Measures or retries the wrong thing, since no awaiting happens |
