# Async generators: the shape of every streaming LLM response

## 1. Why this shape
An LLM streams its answer as many small chunks (tokens). Each chunk arrives **later**, after a network wait. So I need something that:
- gives values **one at a time** (like a generator), and
- can **wait between values** without blocking (like a coroutine).

That is an **async generator**: an `async def` that contains `yield`. Every streaming client (OpenAI, Anthropic, `httpx` streaming responses, FastAPI streaming) hands me one.

## 2. Writing one
```python
import asyncio

async def tokens(text: str):
    for word in text.split():
        await asyncio.sleep(0.05)        # pretend the network is slow
        yield word                        # hand one value to the caller
```
| | Generator | Async generator |
|---|---|---|
| Defined with | `def` + `yield` | `async def` + `yield` |
| Can `await` inside | No | **Yes** |
| Consumed with | `for` | **`async for`** |
| Next value by hand | `next(g)` | `await anext(g)` |

Calling it does not run anything. It returns an `async_generator` object:
```python
g = tokens("hello big world")
print(type(g).__name__)                   # async_generator
```

## 3. Consuming it: `async for`
```python
async def main():
    async for token in tokens("hello big world"):
        print(token, end=" ", flush=True)   # hello big world, one at a time

asyncio.run(main())
```
- `async for` only works **inside an `async def`**.
- Between tokens, the event loop is free to run other tasks, so one server can stream to many users.
- A plain `for` fails clearly: `TypeError: 'async_generator' object is not iterable`.

`end=" "` and `flush=True` is how a chat answer appears word by word.

## 4. Same ideas as normal generators
**Lazy and one at a time.** Values are produced only when asked for. Nothing is stored in a big list.

**Pipelines.** One async generator can consume another:
```python
async def upper(source):
    async for token in source:
        yield token.upper()

async for t in upper(tokens("a b c")):
    print(t)                              # A B C
```
**Stopping early.**
```python
async def take(source, n):
    count = 0
    async for token in source:
        yield token
        count += 1
        if count >= n:
            return                        # ends this generator

async for t in take(tokens("one two three four five"), 2):
    print(t)                              # one, two
```
**Comprehensions work, with `async for`:**
```python
words = [t async for t in tokens("p q") if t != "p"]    # ['q']
```
This collects the whole stream into a list, which defeats streaming, but is handy for tests.

## 5. Manual stepping and closing
```python
g = stream()
first = await anext(g)                    # next value
second = await anext(g)
await g.aclose()                          # stop it now
```
- `anext(g)` is the async `next`. When the stream is finished it raises `StopAsyncIteration` (a plain `async for` handles this for me).
- `aclose()` throws a `GeneratorExit` into the generator at its current `yield`, so its `finally` block runs.

## 6. Cleanup: the part that goes wrong
Use `try`/`finally` inside the generator for resources such as connections:
```python
async def stream():
    try:
        for i in range(5):
            await asyncio.sleep(0.01)
            yield i
    finally:
        print("stream closed")
```
What I measured:
- Running to the end, or calling `await g.aclose()`: `stream closed` printed **immediately**.
- Using `break` inside `async for`: `after break` was printed **before** `stream closed`. The generator was closed *later*, not at the `break`.

When cleanup must happen now, wrap the stream in `aclosing`:
```python
from contextlib import aclosing

async with aclosing(stream()) as s:
    async for x in s:
        if x == 1:
            break                         # leaving the with-block closes it right away
```
Libraries that return streaming responses usually give me an `async with` for this reason, and I should use it.

## 7. Streaming with resources and timeouts
```python
from contextlib import asynccontextmanager

@asynccontextmanager
async def connection():
    print("open")
    try:
        yield "conn"
    finally:
        print("close")

async with connection() as conn:
    async for token in tokens("a b"):
        print(token)
# open, a, b, close
```
Real streaming clients look like this:
```python
async with client.stream("POST", url, json=payload) as response:   # opens, then closes the connection
    async for line in response.aiter_lines():                       # an async generator of lines
        ...
```
A timeout covers a whole stream, since it wraps the whole block:
```python
try:
    async with asyncio.timeout(0.08):
        async for token in tokens("a b c d e f"):
            print(token)
except TimeoutError:
    print("stream timed out")             # measured: got 'a', then timed out
```
It cancels the stream at its next `await`, so the generator's `finally` runs.

## 8. The usual shape of an LLM call
```python
async def stream_answer(prompt: str):
    async with client.stream(...) as response:        # open the connection
        async for line in response.aiter_lines():
            chunk = parse(line)                        # turn raw text into a token
            if chunk:
                yield chunk                            # hand it to my caller

async def main():
    parts = []
    async for chunk in stream_answer("Explain GIL"):
        print(chunk, end="", flush=True)               # show it live
        parts.append(chunk)
    answer = "".join(parts)                            # keep the full text
```
**Open the connection, loop over incoming lines, parse, yield tokens, consume with `async for`, join at the end.** FastAPI's `StreamingResponse` accepts an async generator directly.

## Comparing with JavaScript
| JavaScript | Python |
|---|---|
| `async function*` | `async def` with `yield` |
| `for await (const x of gen())` | `async for x in gen()` |
| `await gen.next()` | `await anext(g)` |
| `gen.return()` | `await g.aclose()` |
| Reading response chunks from a `ReadableStream` | `response.aiter_lines()` / `aiter_bytes()` |
| `for await` closes the iterator on `break` | `break` does **not** close it immediately; use `aclosing` |

## Common mistakes
| Mistake | What happens |
|---|---|
| Using `for` instead of `async for` | `TypeError: 'async_generator' object is not iterable` |
| Using `async for` in a normal `def` | `SyntaxError` |
| `return value` in an async generator | `SyntaxError`: only a bare `return` is allowed |
| Collecting the whole stream into a list | Loses streaming, and uses memory |
| Relying on `break` to close the connection | Cleanup is delayed; use `aclosing` or `async with` |
| Swallowing `CancelledError` in the generator | Timeouts and cancellation stop working |
| Blocking calls (`time.sleep`, `requests`) inside the generator | Freezes the loop between tokens |
| Not handling errors mid-stream | The answer is cut off with no warning |
| Reusing an exhausted stream | It is empty; a generator can be consumed only once |
