# Tasks, `TaskGroup`, `Semaphore`, `timeout` and cancellation

Setup used in the examples:
```python
async def work(name, delay, fail=False):
    await asyncio.sleep(delay)
    if fail:
        raise ValueError(f"{name} failed")
    return name
```

## 1. `create_task`: start now, collect later
```python
task = asyncio.create_task(work("a", 0.3))
# ... other work ...
result = await task
```
- It returns a `Task` at once. The task starts running at the next `await`.
- A `Task` is a `Future` that wraps a coroutine. It has `done()`, `result()`, `cancel()` and `cancelled()`.
- I must **keep a reference** to it. The loop holds only a weak reference, so a task I don't store can be garbage collected mid-run.
- If a task fails and I never await it, I only see `Task exception was never retrieved` when it is collected.

## 2. `gather`: wait for many
```python
results = await asyncio.gather(work("a", 0.1), work("b", 0.1))   # ['a', 'b'], in input order
```
What happens when one fails (measured):
```python
await asyncio.gather(work("a", 0.1, fail=True), slow_task)
# raised: a failed | slow task done? False
# ...later: the slow task finished anyway
```
- By default the **first exception is raised** from `await gather(...)`.
- The **other tasks are not cancelled.** They keep running in the background, which is easy to miss.
- With `return_exceptions=True`, nothing is raised. Errors come back in the list:
```python
await asyncio.gather(work("a", 0.1, fail=True), work("b", 0.1), return_exceptions=True)
# [ValueError('a failed'), 'b']
```
That is `Promise.allSettled`. Then I check each item with `isinstance(r, Exception)`.

## 3. `TaskGroup`: the safer default (Python 3.11+)
```python
async with asyncio.TaskGroup() as tg:
    t1 = tg.create_task(work("a", 0.1))
    t2 = tg.create_task(work("b", 0.1))
# the block waits here until every task is done
print(t1.result(), t2.result())          # a b
```
- Leaving the `async with` block **waits for all tasks**.
- If one task fails, the group **cancels the others** and raises. No task is left behind.
- Several failures arrive together as an `ExceptionGroup`, handled with `except*`:
```python
try:
    async with asyncio.TaskGroup() as tg:
        tg.create_task(work("ok", 0.5))
        tg.create_task(work("bad", 0.1, fail=True))
        tg.create_task(work("bad2", 0.1, fail=True))
except* ValueError as eg:
    print([str(e) for e in eg.exceptions])   # ['bad failed', 'bad2 failed']
```
The `ok` task was cancelled when `bad` failed.

| | `gather` | `TaskGroup` |
|---|---|---|
| One task fails | Raises, but the rest keep running | Cancels the rest, then raises |
| Many failures | Only the first is raised | All, as an `ExceptionGroup` |
| Needs a `with` block | No | Yes |
| Good for | Quick "run these and give me a list" | Anything where a leftover task would be a bug |

## 4. `as_completed`: results as they finish
```python
coros = [work("slow", 0.3), work("fast", 0.1), work("mid", 0.2)]
for fut in asyncio.as_completed(coros):
    print(await fut)                 # fast, mid, slow
```
Order is by **finish time**, not input order. It is the async version of `concurrent.futures.as_completed`. Use it to show or save each result immediately. The returned item is not tied to its input, so if I need to know which input it was, I return it inside the result (`return (name, value)`).

## 5. `Semaphore`: limit how many run at once
Starting 1,000 requests at once would hit rate limits (`429`). A `Semaphore(n)` lets at most `n` tasks into a block at the same time:
```python
sem = asyncio.Semaphore(3)

async def call(i):
    async with sem:                  # waits here if 3 are already inside
        await asyncio.sleep(0.2)     # the real API call goes here

await asyncio.gather(*(call(i) for i in range(9)))
```
Measured: 9 calls with a limit of 3 took **0.61 s** (three waves of 0.2 s), and the peak number inside at once was exactly **3**.

- All 9 tasks are **created** at once, but only 3 do the guarded work. The rest wait cheaply.
- Put `async with sem:` around **only the call** that needs limiting, not the whole function.
- Create it inside the running loop (inside `main`) and **share** one for all tasks.
- It limits *concurrency* (how many at once), not *rate* (calls per minute).
- It is the async version of `ThreadPoolExecutor(max_workers=n)`.

Common pattern:
```python
async def bounded(item):
    async with sem:
        return await call_api(item)

results = await asyncio.gather(*(bounded(x) for x in items), return_exceptions=True)
```

## 6. `asyncio.timeout`: don't wait forever
```python
try:
    async with asyncio.timeout(0.3):
        await work("slow", 1)
except TimeoutError:
    print("too slow")                # measured: after 0.31 s
```
- It covers **everything inside the block**, so several awaits share one budget.
- On expiry it cancels the inner work and raises the built-in `TimeoutError` (3.11+).
- The older single-call form: `await asyncio.wait_for(work("slow", 1), timeout=0.2)`.
- It can only interrupt at an `await`. It does not stop a thread or a blocking call.

Every network call needs a timeout. A hung request otherwise waits forever, and with a `Semaphore` one stuck call permanently takes a slot.

## 7. Cancellation
```python
async def job():
    try:
        await asyncio.sleep(5)
    except asyncio.CancelledError:
        print("job: cleaning up")
        raise                          # always re-raise
    finally:
        print("job: finally")

t = asyncio.create_task(job())
await asyncio.sleep(0.1)
t.cancel()
try:
    await t
except asyncio.CancelledError:
    print(t.cancelled())               # True
```
Measured output: `job: cleaning up`, `job: finally`, then `True`.

- `task.cancel()` **requests** cancellation. At the task's next `await`, a `CancelledError` is raised **inside** it.
- The task can clean up in `finally` (close connections, release resources).
- It **must re-raise** `CancelledError`. If I swallow it, the task refuses to stop, and `TaskGroup` and `timeout` stop working properly.
- `CancelledError` is a `BaseException`, not an `Exception`, so a plain `except Exception:` does **not** catch it.
- A task running code without an `await` cannot be cancelled until it reaches one.

`timeout` and `TaskGroup` both use cancellation underneath.

## Choosing
| Need | Use |
|---|---|
| Run a few things at once and wait for all | `gather` or `TaskGroup` |
| One failure must stop everything cleanly | `TaskGroup` |
| Failures are OK, collect them | `gather(..., return_exceptions=True)` |
| Handle each result as soon as it's ready | `as_completed` |
| Limit simultaneous API calls | `Semaphore` |
| Give up after N seconds | `asyncio.timeout` |
| Stop a task early | `task.cancel()` |

## Comparing with JavaScript
| JavaScript | Python |
|---|---|
| `Promise.all` | `gather` (or `TaskGroup` to cancel the rest on failure) |
| `Promise.allSettled` | `gather(..., return_exceptions=True)` |
| First-done handling | `as_completed` |
| `AbortController` / `AbortSignal.timeout` | `task.cancel()` / `asyncio.timeout` |
| `p-limit` library | `asyncio.Semaphore` (built in) |
| Promises cannot be cancelled | Tasks can: `CancelledError` is raised at the `await` |

## Common mistakes
| Mistake | What happens |
|---|---|
| Not keeping a reference to a task | It can be collected before finishing |
| Assuming `gather` cancels the rest on failure | The others keep running |
| Catching `CancelledError` and not re-raising | The task can't be cancelled; timeouts misbehave |
| `except Exception` to catch cancellation | Won't catch it (`BaseException`) |
| One `Semaphore` per task | Limits nothing |
| Holding the semaphore around the whole function | Needlessly serialises work |
| No timeout on network calls | One hung request blocks a slot forever |
| `await` inside a loop instead of `gather`/`TaskGroup` | Sequential, no speed-up |
| Expecting `timeout` to stop a blocking call | It only works at `await` points |
