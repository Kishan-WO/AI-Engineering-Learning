# Use cases: what embeddings are used for

One vector per text, and a way to measure closeness, supports a whole family of tasks. Semantic search is the first one I build. The others use the same vectors in a different way.

## 1. Semantic search
- **What:** given a query, find the documents closest in meaning.
- **How:** embed the query, score it against all document vectors, take the top `k` (the NumPy search of task 3).
- **Where it goes:** `POST /search` on Day 10, retrieval for RAG from Day 12.
- **Watch for:** exact identifiers and rare terms (keyword search is better there), and chunks that do not make sense alone.

## 2. Classification
- **What:** assign a text to one of several labels (my Day 7 router intents: admission, fees, schedule, academic, complaint, other).
- **Three ways with embeddings:**
  1. **Nearest examples:** embed a few labelled examples per class; a new text gets the label of its nearest examples.
  2. **A small classifier:** train logistic regression on the vectors with labels. A few hundred labelled examples are often enough.
  3. **Label descriptions:** embed the label names or descriptions and pick the closest one, with no training data at all (zero-shot).
- **Compared with a chat model as a classifier (Day 7 and 8):** an embedding classifier costs a fraction of a cent per thousand texts and runs in milliseconds, but it cannot reason about rules like "a problem that already happened is a complaint". It is a candidate for the router's first step.
- **Watch for:** classes that differ by rules and not by topic.

## 3. Clustering
- **What:** group texts without labels, to see what is in a pile (support tickets, questions, documents).
- **How:** run k-means (a number of groups is chosen) or HDBSCAN (the number is found) on the vectors; then read a few items per group to name it.
- **Watch for:** the groups are mathematical, not named. A group can mix two topics or split one in two, so reading samples is part of the method.

## 4. Deduplication
- **What:** find texts that repeat (exact copies, near copies, rewordings).
- **How:** compute all pairwise similarities (`docs @ docs.T`, shape `(n, n)`), ignore the diagonal, and flag the pairs above a threshold. That is task 7.
- **Watch for:**
  - the threshold is chosen by reading the pairs around it (note 3), not copied;
  - two chunks of the same page that begin the same way can look like duplicates;
  - near-duplicates that differ in one fact (a price, a date) are the dangerous ones: they look identical to the model and are not;
  - the `(n, n)` matrix is fine for thousands of texts and too large for millions (then an index is used).

## 5. Recommendation
- **What:** "more like this": similar articles, related questions, products.
- **How:** take an item's vector and return its nearest neighbours. For a user, average the vectors of what they liked and search with the average.
- **Watch for:** closeness in meaning is not the same as what a user wants next; embeddings give a starting list that other signals (popularity, recency, behaviour) adjust.

## 6. Anomaly detection
- **What:** find texts that do not fit the rest (an odd support message, a strange log line, an off-topic document in a corpus).
- **How:** a text far from its nearest neighbours or from the centre of the collection is an outlier candidate.
- **Watch for:** "far" means "different", not "wrong". The list is for a person to review, and a rare but legitimate type of text will appear in it.

## 8. What they have in common
- One embedding of each text, made once and stored (the `.npy` file and its metadata).
- A similarity measure (cosine on normalised vectors).
- A decision on top of the scores: take the top `k`, apply a threshold, or group.
- A human check of the result, because a similarity score is not a judgement.
