# Hallucination

## 1. What it is
A **hallucination** is when the model writes something that sounds right but is **false or made up**: a fact, a number, a quote, a name, a source, or a function that doesn't exist.

```
Q: "Give me a paper on this niche topic."
A: "Sharma, R. and Iyer, K. (2019). Adaptive Caching in Edge Clusters. Journal of Distributed Systems, 41(3), 112-130."
```
That looks like a real citation: authors, year, title, journal, volume, pages. It may not exist at all.

Common forms:
- **Invented facts** (dates, statistics, biographies)
- **Invented citations and links** (papers, court cases, URLs)
- **Invented code or APIs** (a library function or parameter that doesn't exist)
- **Wrong details inside a correct answer** (right person, wrong year)
- **Confident answers to impossible questions**

## 2. Why it happens
It follows directly from how the model works:
- The model **predicts likely next tokens**. It produces text that *fits the pattern* of a good answer.
- A real citation and an invented one look the same in pattern, so both are "likely".
- It has **no built-in check** that says "is this true?". Writing and fact-checking are different jobs.
- It was trained to **give a fluent answer**, so "I don't know" is less likely unless it was trained to say it.
- Rare facts are weak in its memory: for obscure topics it fills the gaps with plausible text.
- Details are stored as patterns, not as a database. It remembers the shape of a fact and rebuilds the details.
- A wrong token early in the answer is followed by tokens that fit the mistake, so the error grows.

## 3. It is a property, not a bug
- It comes from the same mechanism that makes the model useful: generating likely text.
- Newer and bigger models hallucinate **less**, not **never**.
- A more careful model may also refuse or hedge more, which is a trade-off.
- Setting temperature to 0 makes output steadier, **not truer**. The most likely wrong answer is still wrong.

So the goal is **not** to remove it but to **reduce it and catch it**.

## 4. When it is most likely
| Situation | Why |
|---|---|
| Niche or rare topics | Little training text about them |
| Exact details: numbers, dates, names, quotes | These must be exact; "close" is wrong |
| Citations, links, case numbers, IDs | Look the same whether real or invented |
| Recent events (after the cutoff) | The model never saw them |
| Questions with a false premise | "When did X win the 2019 prize?" when X never did |
| Long answers | More tokens, more chances for an error to start |
| Private data the model never saw | It guesses instead of saying it doesn't have it |

## 5. Why it is dangerous
- It is **confident**: the tone doesn't change between right and wrong.
- It is **plausible**: errors look professional, with formatting and references.
- It is **unpredictable**: right 20 times, wrong on the 21st.
- Users trust fluent text, so errors spread (wrong advice, fake legal citations, bad code in production).

## 6. How to reduce and catch it
| Idea | How it helps |
|---|---|
| **Grounding** (give the facts in the prompt, for example by retrieving documents) | The model answers from supplied text instead of its memory |
| **Structured outputs** | A fixed format lets a missing value be `null` instead of invented |
| **Tool use** | Let code do exact work: a calculator, a database query, a search |
| **Evaluation** | Test answers against known correct examples to measure how often it fails |
| **Permission to say "I don't know"** | Tell the model to answer only from the given text, and to say so when it can't |
| **Ask for quotes from the text** | Easier to verify; unsupported claims stand out |
| **Lower temperature** | Fewer random wrong turns (but doesn't make it true) |
| **Human review** | For high-stakes answers, a person checks before use |

A simple prompt habit: *"Use only the text below. If the answer is not in it, say 'not found'."*

## 7. How to check a citation (the day's experiment)
1. Search the exact **title** in a search engine or Google Scholar.
2. Check that the **authors, year and journal** match the real record.
3. Open the link or **DOI** and confirm it points to that paper.
4. Check the **claim**: even a real paper may not say what the model says it says.
5. Record how many were real, how many invented, and how many real but misdescribed.

## Common mistakes
| Mistake | Reality |
|---|---|
| "Hallucination is a bug they will fix" | It comes with next-token prediction; it can be reduced, not removed |
| "Temperature 0 stops hallucination" | It makes output steadier, not truer |
| "If it gives sources, it is accurate" | Sources can be invented |
| "A confident tone means correct" | Tone says nothing about truth |
| "Big models never hallucinate" | They do it less, not never |
| "It only happens on hard questions" | It also happens on easy-looking ones |
