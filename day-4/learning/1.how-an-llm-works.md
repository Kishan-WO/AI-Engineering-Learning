# How an LLM works (practical level)

No maths here, only the ideas I need to use these models well.

## 1. The one idea: predict the next token
An LLM does one job: given the text so far, it predicts **the next small piece of text** (a token). Then it adds that piece to the text and predicts the next one, again and again.

```
Prompt:   "The capital of France is"
Step 1:   → " Paris"          text is now "The capital of France is Paris"
Step 2:   → "."              text is now "The capital of France is Paris."
Step 3:   → <end>            stop
```
- A long answer is just this loop run hundreds of times.
- Each step looks at the **whole text so far** (my prompt plus the tokens already written).
- The model never plans the whole answer first and then writes it. It decides one token at a time.

Autocomplete on a phone keyboard works the same way, only trained on far more text.

## 2. What the model outputs at each step
At each step the model does not pick one word. It gives a **probability for every token** it knows (tens of thousands):

| Next token after "The capital of France is" | Probability |
|---|---|
| " Paris" | 0.92 |
| " the" | 0.02 |
| " located" | 0.01 |
| … thousands more, all tiny | … |

Then one token is **chosen** from that list. How it is chosen is controlled by settings such as temperature.
- Most of the time the likely token wins, so answers are mostly stable.
- Sometimes a less likely token is picked, and the text goes a different way from there.

## 3. Why the output is probabilistic
A token is *chosen* from a probability list, not looked up:
- The **same prompt can give different answers** on different runs.
- A small difference early in the answer changes everything after it, because each token feeds into the next.
- The model produces what is **likely**, not what is **verified**. That is why it can sound sure and still be wrong.

## 4. Three training stages
| Stage | What happens | What it adds |
|---|---|---|
| **1. Pretraining** | Reads a huge amount of text (web pages, books, code) and learns to predict the next token | Language, facts, patterns, code, general knowledge. At this point it only *continues* text; it does not follow instructions |
| **2. Instruction tuning** | Trained on examples of questions with good answers | It learns to **follow instructions** and answer in a helpful format |
| **3. Preference tuning** (RLHF or DPO) | People (or a judge model) compare two answers and mark the better one; the model is nudged towards the preferred style | Answers that are more helpful, safer, politer and better matched to what people like |

In short: **knows a lot** (pretraining) → **does what I ask** (instruction tuning) → **answers the way people prefer** (preference tuning).

A model after stage 1 only, asked "What is the capital of France?", might continue with another quiz question. After stages 2 and 3 it answers "Paris."

## 5. The transformer, at intuition level
1. **Tokens become vectors.** Each token is turned into a long list of numbers (an *embedding*). Tokens with related meaning get similar numbers.
2. **Attention.** For each token, the model looks at all the other tokens and decides **which ones matter for it**. In "The trophy didn't fit in the suitcase because **it** was too big", attention helps link "it" to "trophy".
3. **Stacked layers.** This repeats layer after layer. Early layers handle simple patterns (grammar), later layers handle meaning and context.

At the top, the last layer turns the result into the probability list from section 2.

What this means for me:
- The model can use **any part of the text it was given**, so the clarity and position of my instructions matter.
- It only "knows" what is in its weights (training) plus the text I send.
- The cost of attention grows with the length of the text, so long prompts cost more.

## 6. Reasoning ("thinking") models
Some models are trained to **write out their thinking first**, then give the final answer.
- They spend **extra tokens** on working steps (often shown separately or hidden).
- They are **better at hard tasks**: maths, logic, multi-step problems, tricky code.
- They are **slower and more expensive**, because the thinking tokens take time and are billed.

| | Normal model | Reasoning model |
|---|---|---|
| Speed | Faster | Slower |
| Cost | Lower | Higher (thinking tokens count) |
| Best for | Chat, summaries, extraction, simple Q and A | Hard problems, planning, multi-step logic |

Rule of thumb: use a normal model by default, and a reasoning model when the task is hard and a wrong answer is costly.

## 7. What this means in practice
- **It predicts, it doesn't look things up.** Facts can be wrong, and plausible details can be invented.
- **Output varies** unless the randomness is reduced.
- **It follows the text it sees.** Clear instructions and good examples change the result a lot.
- **Bigger or reasoning models cost more** and take longer, so pick by need.

## Common mistakes
| Mistake | Reality |
|---|---|
| "The model looks up the answer" | It predicts likely text token by token |
| "It thinks about the whole answer first" | It chooses one token at a time (reasoning models write their thinking out as tokens) |
| "Same prompt, same answer" | Not guaranteed, because a token is chosen from probabilities |
| "It is confident, so it is right" | The confidence of the wording says nothing about accuracy |
| "A reasoning model is always better" | It is slower and costlier; for simple tasks it adds nothing |
