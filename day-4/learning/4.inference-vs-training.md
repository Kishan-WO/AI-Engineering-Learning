# Inference vs training

## 1. Two different phases
| | Training | Inference |
|---|---|---|
| What happens | The model **learns**: its numbers (weights) are adjusted | The model **runs**: it uses its weights to produce an answer |
| When | Before release, once, over weeks or months | Every time I call the API |
| Who does it | The model builder, on huge computer clusters | The provider's servers (or my laptop for a local model) |
| Cost | Enormous (millions of dollars for large models) | Small per call, but it adds up with use |
| Do the weights change? | **Yes** | **No** |

Everything I do with an API (chat, extraction, summaries) is **inference**. I am using a finished model, not teaching it.

## 2. Weights are frozen at inference
The **weights** are the billions of numbers that hold everything the model learned. When I call the model:
- The weights are **read, never written**.
- The same model serves millions of users with exactly the same weights.
- Nothing I type changes them.

So **my prompt does not teach the model anything permanent.**

```
Me:     "From now on, my favourite colour is green."
Model:  "Got it, I'll remember that!"
(next call, new conversation)
Me:     "What's my favourite colour?"
Model:  "I don't know."
```
- The first reply sounds like learning, but it is the model continuing the text politely.
- Inside that **one call** it can use what I wrote, because the text is in its input. This is temporary.
- This temporary use of the prompt (rules, examples, documents) is often called **in-context learning**. The model adapts to the prompt without changing at all.

## 3. Why correcting the model doesn't "fix" it
- In the same conversation, it usually accepts a correction, because the correction is in the history.
- In a **new** conversation, the same mistake can come back, because the weights did not change.
- For my own app, the lasting fix is to put the right information into the **prompt** every time, or to change the model (training), not to hope it learned.

## 4. What changes the model: training and fine-tuning
| Method | What it does | When it makes sense |
|---|---|---|
| **Pretraining** | Builds the model from scratch on huge text | Only the big labs |
| **Fine-tuning** | Continues training on my own examples (a smaller dataset) | To change **style, format or behaviour** that prompting can't fix reliably |
| **Preference tuning** | Trains on "better vs worse" answers | Aligning the model to preferred behaviour |

- Fine-tuning is **not the best way to add facts**. Facts added this way are unreliable and go out of date.
- Prompts are cheap and instant to change. Fine-tuning needs data, money and time, and must be redone for new models.
- Try the prompt first, and fine-tune only when a prompt clearly can't do the job.

## 5. Knowledge cutoff dates
A model's knowledge stops at a **cutoff date**: the end of its training data.
- It knows nothing that happened after the cutoff. Asked about newer events, it may say it doesn't know, or **make something up**.
- It usually has **no clock**. Unless I tell it, it doesn't know today's date.
- A model is released **months after** its cutoff and then used for a year or more, so it is always behind.
- It is also less sure about the last stretch before the cutoff, because there was less text about it yet.

| Problem | What to do |
|---|---|
| Needs today's date | Put the current date in the prompt |
| Needs recent facts or news | Send the facts in the prompt, or let the model fetch them |
| Needs my company's data | Send the relevant data in the prompt (the model never saw it in training) |
| Needs the newest library or API | Paste the current docs into the prompt |

## 6. Privacy: does my data train the model?
Inference alone does not change the weights. But a provider may still **store my requests** and, depending on its policy and plan, may use them to improve future models.
- This is a policy question. I check the provider's terms for API and business use.
- I don't send passwords, personal data or secrets unless the terms allow it.

## 7. What this means in practice
- **Treat each call as a fresh start.** Whatever the model needs must be in the input.
- **Put facts, rules and examples in the prompt.**
- **Give the model today's date** when it matters.
- **Don't expect corrections to stick** across conversations.
- **Fine-tune last**, not first.

## Common mistakes
| Mistake | Reality |
|---|---|
| "I told the model my name, it learned it" | Only for that conversation, because it is in the history |
| "Correcting the model improves it for everyone" | Weights don't change at inference |
| "Fine-tuning is the way to add my documents" | Unreliable for facts; put the facts in the prompt |
| "The model knows today's date" | It has no clock; tell it |
| "The model knows the latest news" | It stops at its cutoff date |
| "Prompts and training are the same" | A prompt is temporary input; training changes weights |
